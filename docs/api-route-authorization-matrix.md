# API route authorization matrix

The API capability gate is mounted before `/api` handlers in `server.ts`. For
`/api/v1/*`, the registry matches the path after `/api/v1`; for other `/api/*`
paths, only the legacy `/api/health` registration is allowed. Unmatched routes
and routes whose capability is not ready return `503
PRODUCTION_PERSISTENCE_UNAVAILABLE` before their handlers run. A mounted route
is not, by itself, evidence that the route is available.

The table lists every route pattern the capability registry can admit. `:uuid`
means the registry's UUID pattern; other parameter names match the corresponding
registry expression. A route not listed here is blocked by the default-deny
gate, including mounted legacy handlers and AI routes without a ready
registration.

## Routes deliberately not enabled

The capability gate also covers mounted handlers that are not in an enabled
registration. Such routes are classified as **blocked**, not public or
authenticated: the gate returns 503 before the route-specific handler or
middleware executes. This includes unmatched legacy `/api/*` routes, unmatched
`/api/v1/*` routes, and `/api/ai/v1/*`; no AI capability is enabled by this
matrix. The `administrative_permissions` registration reserves membership and
role paths, but those handlers do not exist yet. Do not mark those capabilities
ready or add frontend-only access controls.

The matrix is derived from `server/capabilities/productionCapabilityRegistry.ts`.
The registry is the enforcement source of truth; tests in
`server/capabilities/productionCapabilityRegistry.test.ts` verify that unready
and unknown routes stay blocked and that the gate precedes API handler
registration.

New question-bank items, including starter imports, are created as drafts or
pending review. Approval requires the separate `question_bank.review` route.
This does not retroactively verify previously approved items, and does not
make the existing examination or browser-only CBT prototypes production-ready.

The versioned `adaptive-remedial-secure-cbt` feature template is a draft and
cannot be provisioned. The Curriculum Flow question-bank and secure examination
tabs show an unavailable notice rather than their mock prototypes. The remedial
tab reads class-level flags from authenticated teaching evidence; it does not
identify individual gaps or provide an intervention workflow. Automatic instance
lookup uses the currently blocked school-profile route; an authorized user may
enter an application instance ID, which remains subject to tenant and teacher
scope checks on the teaching endpoints.
Secure sessions, a release vault, marking, publication, and real intervention
records remain unimplemented; managed kiosk integration is required for
operating-system lockdown. Do not remove the question-bank write gate until
resource-scoped authorization, review, audit, and acceptance evidence exist.
